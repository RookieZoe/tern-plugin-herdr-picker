# What Tern's iOS client offers plugins

Research for issue #3 (map: issue #2). Checked on 2026-11-24 against Tern 0.9.32 (`tern --version` →
`0.9.32 (0dd129e)`) on macOS, its online plugin docs, the changelog and strings built into the macOS
binary, and one screenshot from a real iPhone.

Each answer is marked **confirmed** (a primary source says so) or **inferred** (follows from sources
but nothing states it). Points only a real iPhone can settle are collected at the end.

## Summary

- The phone runs **window halves only**, from its **own** plugins folder (Files app › On My iPhone ›
  Tern › Plugins). It never runs `host.luau`, its own or the host's. The host's daemon runs the host's
  `host.luau` for the host's panes, phone-opened ones included, and the phone shows the resulting
  blocks and lens views.
- Plugin block kinds reach the phone through the host's **catalog**. Whether the phone's **New (+)**
  sheet lists them is not documented and the binary doesn't settle it; it needs a device test.
  The phone has no command palette as such; its drawer has a **search pill "in place of the command
  palette"** that finds actions, which probably includes plugin `tern.command` rows (unconfirmed).
- `cx:pick`, `cx:prompt`, `cx.layout:split` (with `command`) and `tern.kv` are not marked
  desktop-only anywhere, so they are expected to work on iOS (inferred). `split` runs its command on
  the **target pane's host**, so `hc attach` would run on the Mac (confirmed for desktop, applies to
  iOS by the same rule). `tern.kv` on the phone is the phone's own store, not the Mac's (inferred).
  `tern.process.run` raises (confirmed); `tern.fetch` works (confirmed).

## 1. Does the iOS window load plugins, and from where?

**Window halves load on iOS, from the phone's own folder: confirmed.**

- "The iOS client runs window halves from its Files-app plugins folder (see Packages and Manifests)
  in the interpreter, and skips host entries. It shows blocks and lens views from the hosts it is
  attached to." [arch]
- Support Matrix row "Window half (window entry)": iOS **Yes**; "Host half (host entry)": iOS **No;
  host entries are skipped**. [matrix]
- The folder: "On iOS the folder is the app's Documents/Plugins, which the Files app shows as On My
  iPhone (or iPad) › Tern › Plugins. iOS has no command line or git: copy a package folder there."
  [pkg] Reload with Preferences › Plugins › Reload or the palette's Reload plugins; the folder is
  also polled every 2 s. [dist] [pkg] The same since plugins were added in 0.4.0: "a folder with a
  `plugin.toml` in the plugins folder (`tern plugin dir`; on iOS, Tern's Plugins folder in the Files
  app)". [cl 0.4.0]
- No `tern plugin` CLI on iOS. [matrix]
- Runs interpreted, no JIT (`tern.runtime.jit` false). [matrix] [dts]

**A host-installed plugin's window half does not run on the phone: confirmed.** "Your window half
is local: it runs from your plugins folder and sees every pane in your windows, local and remote."
[arch] The catalog a host sends carries ids, block types, lens rules and styles, not window code.
[arch "The catalog"] So `plugin/window.luau` installed on the Mac does nothing on the phone; it has
to be copied into the phone's Files-app folder.

**`host.luau` of a host-installed plugin serves panes the phone opens: confirmed by the architecture,
not tested on a device.** Host halves run "On the remote host, in its daemon, from its plugins
folder" [arch table], and "blocks and lenses come from the hosts the app is attached to, and appear
as long as those hosts have the plugin installed" [dist]. "iOS runs no host halves, so plugin blocks
run only on the hosts an iOS device connects to." [api, troubleshooting] A pane the phone opens is a
pane of the Mac's daemon, so the Mac's host half sees it like any other (blocks, lenses, hooks).

Also: a window half on iOS "still acts on every pane in the window, all of which belong to remote
hosts." [matrix notes]

## 2. Does the iOS new-pane UI list plugin block kinds? Is the palette reachable?

### The New (+) sheet

**What it shows today: confirmed [shot].** Tapping "new" on a pane in a tab opens a sheet titled
"New in `<session>@macmini`" with:

- a folder picker (the cwd, e.g. `/Users/zoe/Codes…`) and a **New tab / In tab** toggle;
- a grid: Terminal (login shell), Agent (omp), Git, Files, Note (Markdown), Carly (assistant);
- a list "Workspace blocks": Browser preview (URL / localhost), Task board (TODO.md), SQLite
  database (.db / memory), Notebook (.ipynb), Canvas (sketch), Processes (task manager), Remote
  screen (live display).

The user has no plugin with a `[[blocks]]` entry installed on `macmini`, so the screenshot can't
show whether plugin blocks would appear.

The changelog describes it: "**New** (+) creates any block in one tap". [cl 0.9.14] The binary holds
the sheet's fixed strings in one run ("Where it opens", "In tab", "login shell", "agent chat",
"Agent", "Git", "full-page tree", "Files", "Carly", "Browser preview", "URL / localhost", "Task
board", "SQLite database", ".db / memory", "Notebook", "Processes", "task manager", "Remote screen",
"live display"), its CSS classes `pn-new`, `pn-dir`, `pn-seg`, and the strings "Workspace blocks",
"New in ", "Starts in ", "Choose a folder". [bin] Every native entry has a hard-coded subtitle;
nothing in the strings shows how, or whether, plugin entries join the list.

**Whether "Workspace blocks" lists plugin block kinds: not settled; needs a device.** For it
(inferred):

- The sheet is scoped to the host ("New in …@macmini"), and the host's catalog, which every replica
  including iOS receives, carries each block type's "id, title, icon, files, palette", used for
  "'New title block' palette rows". [arch "The catalog"] So the phone has the data to list them.
- `cx.session:block_types()` returns "native and Ready plugin block types on this window's current
  host" with a `palette` flag [dts], i.e. Tern already keeps one merged list of native and plugin
  kinds per host.
- "creates any block" [cl 0.9.14].

Against: the docs' table of ways to open a block lists the command palette, a file's "Open with",
routes, `cx:new_block` and layouts, but not the phone's New sheet. [blocks "Opening blocks"]

**If plugin blocks are listed (inferred):** a block started from the sheet would get the sheet's
folder as `cx.cwd` ("The pane's working directory when the block started" [api, block cx]) and be
placed by the New tab / In tab toggle. It gets no launch arguments: the palette row passes none
[blocks], and the sheet has no field for them.

### The command palette

**The phone has no command palette as such; a search pill takes its place: confirmed.** "**The
drawer is Home**: your host, a search pill in place of the command palette, what needs you, and
every session". [cl 0.9.14] Its placeholder reads "Search tabs, files, actions" / "Type to find a
tab, a file, an action or a branch." [bin]

**Whether that search finds plugin `tern.command` rows (and "New … block" rows): inferred yes, not
confirmed.** `tern.command` adds an ordinary action `plugin.<plugin>.<id>` [dts], and the pill
searches actions. Nothing says plugin actions are filtered out on the phone. A key bind
(`tern.bind`) is of little use without a hardware keyboard.

## 3. Which window-half calls this plugin uses work on iOS?

| Call | iOS | Evidence |
|---|---|---|
| `tern.process.run` | **Raises** "tern.process is not available on iOS": confirmed | [matrix] [dts] [dist] |
| `tern.fetch` | **Works**, from the phone: confirmed | [matrix] [sec] |
| `cx:pick` | Expected to work: inferred | Not marked desktop-only [api] [dts]; added in 0.7.1 with no platform note [cl] |
| `cx:prompt` | Expected to work: inferred | Same as `cx:pick` |
| `cx.layout:split(target, dir, {command, cwd})` | Expected to work: inferred | `cx.layout` not marked desktop-only [api]; "Splits pane target … **on target's host**, in target's directory unless launch.cwd is set" [api]. On a phone every pane is the Mac's, so the command (`hc attach …`) runs on the Mac |
| `tern.kv` | Works, but on the phone's own store: inferred | `kv.json` lives in `<state>/plugin-data/<id>/` of the machine the VM runs on, shared by the VMs there [arch "Ownership"] [pkg]; the phone's window half runs on the phone. A Mac window's mapping is not visible to the phone |
| `tern.fs` | Works "within what iOS lets the app reach": confirmed | [matrix notes]. It reads the phone, not the Mac, so `tern.fs.list` can't browse the Mac's folders for a new space |
| `cx.session:panes()`, `cx.layout:focus` | Expected to work: inferred | Not marked desktop-only [api] |

Members the docs do mark desktop-only (not used by this plugin): `cx.procs` ("local desktop only"),
`cx.board`, `cx.db`, `cx.whiteboard`, `cx.docs`, `cx.git`, `tern.carly`, `cx.hosts:add`
("Desktop:"), `cx.session:settle`, `cx.agents:wait`. [api] [dts] The plugin's calls are not on that
list.

**What this means for this plugin (inferred):** a copy of today's `window.luau` on the phone fails
at the first `hc` call, because every one goes through `tern.process.run`. The window half could
still show a picker and open a split running `hc attach` on the Mac, if it got the pane list some
other way: from a host half (a block on the Mac), or by `tern.fetch` to something on the Mac that
serves `hc ls --json`.

## What only a real iPhone can settle

1. Does the New (+) sheet's "Workspace blocks" list a host plugin's `[[blocks]]` kind (with
   `palette` true, and with `palette = false`)? Test: install a plugin with one block on `macmini`,
   reload, open the sheet.
2. If it does: does the block get the sheet's folder as `cx.cwd`, and does New tab / In tab place it?
3. Does the drawer's search pill find a phone-installed plugin's `tern.command` rows, and the host's
   "New … block" rows?
4. Do `cx:pick` and `cx:prompt` open on the phone (as a sheet or over the pane), and does an unknown
   icon name still raise there?
5. Does `cx.layout:split(pane, "right", { command = "hc attach …" })` from a phone window half open
   a pane on the Mac running the command (and how does a split look on a phone screen)?
6. `tern.kv` on the phone: confirm it is a separate store from the Mac's.
7. That a copy of `window.luau` in the Files-app folder loads and shows its `tern.command` at all
   (Preferences › Plugins status).
